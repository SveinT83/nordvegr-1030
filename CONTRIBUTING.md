# Contributing to Nordvegr 1030

Contributions are welcome through the official GitHub repository.

## Before contributing

- Read `LICENSE` before submitting anything.
- Only submit work you created yourself or material you have clear rights to contribute.
- Do not add third-party assets, code, scans, maps, audio, models or datasets unless their license is compatible and documented.
- For historical claims, prefer archaeological reports, museum sources, primary sources or reputable academic literature. Record important sources in the relevant documentation or pull request.
- Keep changes focused. Avoid mixing unrelated features, refactors and assets in the same pull request.

## Contribution workflow

1. Fork or clone the repository for the purpose of contributing.
2. Create a dedicated branch for your change.
3. Make and test the change.
4. Open a pull request against the official repository.
5. Explain what changed, why it changed, how it was tested, and any historical or technical sources used.

## Unity-specific rules

- Do not commit `Library/`, `Temp/`, `Logs/`, `UserSettings/` or build output.
- Keep Unity `.meta` files together with their assets.
- Do not upgrade the Unity Editor version, render pipeline or major packages as part of an unrelated change.
- Avoid hand-editing Unity YAML scene or prefab files unless necessary and understood.
- Do not commit generated caches or machine-specific settings.
- Large binary assets should use the repository's chosen large-file workflow when one is configured.

## Rights granted by contributions

By intentionally submitting a contribution, you confirm that you have the right to submit it and agree to the contribution terms in `LICENSE`.

You retain copyright in your original contribution, while granting the official Nordvegr 1030 project the rights needed to use, modify, integrate, distribute and relicense it as part of the project.

If you do not agree to these terms, do not submit the contribution.
